# specs/ — How This Directory Works

This directory holds the **hand-maintained, pre-OpenSpec** specs (Phase 1) and
the ADRs that outlive any single feature. Once you run `openspec init` in
Phase 3, `openspec/specs/` becomes the living source of truth for anything
that's gone through a full propose → apply → archive cycle — but the founding
`constitution.md` and `features/*/spec.md` here are what you start from.

- `constitution.md` — non-negotiable, project-wide constraints. Edited by
  hand, not generated by AI.
- `features/<nnn-name>/` — one folder per backlog feature.
  - `spec.md` — requirements + acceptance criteria / scenarios
  - `tasks.md` — implementation checklist
  - `open-questions.md` — spikes, with a `Status: OPEN | RESOLVED` field
- `decisions/` — ADRs for architectural calls that cut across multiple
  features (e.g., timezone handling strategy affects both streaks and
  reminders).

## Agent instructions

See the repo-root `CLAUDE.md` — Claude Code is instructed to read this
directory (and later `openspec/specs/`) before implementing anything, and to
stop and ask rather than guess when it hits an `OPEN` question relevant to its
task.
